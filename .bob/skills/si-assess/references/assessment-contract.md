# Assessment and annex contract

Use this reference while authoring the consolidated assessment and seven annexes. The report standard and rubric in `.bob/standards/` govern content and adversarial acceptance. Helpers can reject broken structure; they cannot supply professional judgement.

## Identity and origin

Each Markdown artifact starts with the template frontmatter: `version`, `as_of`, `run_id`, `source_revision`, `kit_version`, `author`, `status`, `synthetic_demo`, `target`, `evidence` and `scope`. Resolve every `{{...}}` field from the run or Bob-authored findings before review. Keep `status: pending` until the independent gate changes it; templates and sample JSON are not accepted outputs. The six-file contract uses `assessment.md` and `sow.md`; legacy `assessment-report.md`/`draft-sow.md` names are historical and are not used.

## Findings and decisions

Use one stable `F-` namespace across the assessment, annexes, WBS, SOW and ledger. `findings.json` enumerates known `evidence_ids` and findings with `id`, `title`, legacy-health `category`, business/operational `impact`, `evidence_ids`, ordinal `severity`, `rationale`, nonempty `remediation_options` and explicit `decision_owner`. Its `evidence_dispositions` array covers every accepted evidence ID exactly once. `mapped` lists the exact findings that reference that evidence and has null owner/reason; derive this list from the final findings rather than copying a draft. `deferred` or `accepted_risk` has no finding links and requires a nonempty owner and reason. `accepted_risk` remains a reported proposal until authenticated client acceptance is preserved. Reproduce these rows in an assessment table so the final pack exposes rather than hides unassessed evidence. JSON category values are exactly `documentation`, `coupling`, `dead_code_candidate`, `duplication`, `testability`, `error_data_handling`, `obsolete_dependency`, `security`, `operations`, `architecture` or `other`; Markdown may display friendly labels. The helper requires exact row keys, total closure and resolved references. Optional `security_status` is `not_applicable`, `under_investigation`, `not_affected`, `fixed`, `unreachable` or `exploitable`; all statuses stronger than investigation need nonempty `status_evidence_ids` resolving to the same ledger. Record scan scope, affected component, execution path and exact result in the cited evidence. An evidence link existing is not proof that it supports the claim.

A recommendation compares retain/contain, bounded migration and deeper modernization on disruption, risks, effort basis and unresolved inputs. Name decision owner and evidence that could reverse it. Do not average ordinal scores, assert percentage savings, infer client priorities, or classify static no-call findings as dead code. “Scan not performed” is explicit when no scan ran.

The helper input is a working evidence-link sidecar, not the canonical finding/handoff object. For the [canonical finding contract](../../../schemas/finding.schema.json), Bob carries working `id` into `finding_id`, resolves `evidence_ids` to exact `evidence` path/locator/hash objects, and supplies actual `run_id`, `source_revision`, `evidence_status`, impact, recommendation and open/reviewed status. The sidecar's severity `unknown` is unresolved analysis, not an allowed canonical severity: decide an evidenced ordinal category or leave it as a named unresolved decision. Keep security investigations in the source ledger rather than adding unsupported fields to the canonical schema. Return final findings only in `runs/<name>/data/findings.json`; hashes, cost and gate state belong to the checkers and the user, never to Bob's files. Semantic mapping is Bob's responsibility, never generated by a numeric/resource helper.

## Factory v2 sections

`assessment.md` adds three level-2 sections with exact headings. The report-quality gate checks that each exists and carries its basis; it does not judge whether a score is right.

- **`## Technical debt scoring (SI-measured, Bob-scored)`:** the SI measures and Bob scores. The input is `runs/<name>/inputs/complexity-metrics.json`, written by `tools/metrics/complexity_metrics.py`, with per-file `lines_code`, `method_count`, `max_method_branch_count` and per-method `branch_count`. State the rubric before the scores. Give one table row per component, with metric values copied from the input, the score and its finding IDs. Carry the literal label, cite the input path, and never say Bob measured anything. A metric missing from the input stays unknown.
- **`## Modernisation options scoring`:** state the criteria before the scores: business criticality, technical fit, effort basis, delivery risk and reversibility at minimum. Classify each component against retire, retain, rehost, relocate, repurchase, replatform and refactor, and give a one-line reason for every path rejected. Rate business criticality from evidence, or mark it unknown with an owner. Do not average ordinal scores or infer client priorities.
- **`## Operational history and ticket corroboration`:** use the governed read-only tickets tools when the stage lists them. Classify each record as code-relevant or not. A ticket is a synthetic user report, never a diagnosis.
  - Cite a ticket ID only on the same line as the finding's primary `EV-` evidence. The gate rejects a line that pairs a `DESK-` ticket with a finding but no evidence ID.
  - Never put tickets in `evidence_ids`, and never raise a severity on ticket evidence alone.
  - If the tools are unavailable, record a named gap.
- **Security wording:** `## Security assessment` states "source-reading review, no scanner". Any scan or dependency audit that was not run stays visibly not run.

## Target annexes

Load the selected profiles through [the target profiles](target-profiles.md). Each annex uses consolidated finding IDs, target-specific compatibility constraints, retain/contain and migration options, scoped feasibility tests, cost/effort uncertainty, required client input and pending decision. It makes no independent executive claim and does not imply target implementation. Only the separately authorized Java invoice-preview pilot can have observed implementation results.

The [assessment template](../templates/assessment.md), [annex template](../templates/target-annexes.md) and [findings input](../templates/findings.json) are starting structures. [validate_findings.py](../scripts/validate_findings.py) returns exit 2 on broken evidence/IDs. An independent critic still challenges the actual report versions against the rubric in `.bob/standards/report-quality-rubric.json`.
